## Engineering Focus

I build **developer-facing infrastructure**: systems that coordinate agents, understand repositories, schedule compute, automate software workflows, model infrastructure, and make complex engineering work easier to inspect and operate.

My current work sits across:

- **AI infrastructure** — agent orchestration, tool permissions, memory, task graphs, model/provider interoperability
- **Developer tooling** — repository intelligence, static analysis, migration planning, Git automation, CI and deployment workflows
- **Distributed systems** — worker scheduling, trusted compute, capability matching, failover-oriented architecture
- **Backend & control planes** — APIs, schedulers, state models, validation, CLI systems and service boundaries
- **Polyglot systems engineering** — C++20, Go, Java, TypeScript, Python, JavaScript, SQL and shell tooling
- **Automation & operations** — self-hosted workflows, recovery planning, infrastructure history and reproducible execution
- **Open interoperability** — MCP/A2A-style concepts, adapters, schemas and explicit cross-runtime contracts

### FORGE — Polyglot Repository Modernization Engine

[`nova-spectre777/forge-platform`](https://github.com/nova-spectre777/forge-platform)

A multi-language modernization control plane that separates repository analysis, migration planning, dependency ordering, worker scheduling and operator visualization.

**Architecture:** `C++20 scanner` → `Python planner` → `Go control plane` → `TypeScript console`, with a `Java 21 plugin SDK` for JVM/framework modernization checks.

FORGE is designed around inspectable JSON contracts, migration DAGs, risk scoring, capability-scoped workers and verification-first change planning rather than blind code rewriting.

## Architecture Problems I Like

```text
How should autonomous agents coordinate safely?
How can generated work execute without touching the operator's main workspace?
How do large polyglot repositories get modernized without giant unsafe rewrites?
How can one runtime abstract providers without hiding meaningful differences?
How should distributed workers prove capabilities and expose failures clearly?
How can repository and infrastructure state become queryable, versioned intelligence?
How can software detect, diagnose, verify and recover from failures without opaque magic?
```
